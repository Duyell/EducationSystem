> 面向 Agent / 大模型应用方向。与「社区生鲜配送系统」差异化：通用后端条目
> （Spring Security + JWT + RBAC、Redis 缓存、MyBatis 分层）不写。

## 可粘贴版本

**项目名称：教务系统（个人项目 · Java 后端 + LLM Agent）**

**项目概述**：独立开发的教务系统与内嵌智能助手——用大模型驱动真实的教务业务，
能查数据、能办业务，涉及改数据时先请用户确认。

- **Agent 实现**：基于 **Spring AI 的 Function Calling**，把业务能力用 `@Tool` 声明成工具
  （框架自动生成给模型看的参数说明），再用自研的 **Agent 执行循环**驱动
  "模型请求工具 → 服务端执行 → 结果回填 → 模型继续作答"，直到模型给出最终答案；
  对话通过 **SSE** 流式返回，支持一轮内多次调用工具。
- **权限与安全闸门**：工具执行前后有**四道闸门**——角色白名单、参数校验、危险操作人工确认、审计留痕。
  模型只能看到自己角色的工具；危险操作（选课、录改成绩、审批等）**不直接执行**，而是挂起等用户在界面上
  点确认，**确认前数据库不会有任何变化**；再用幂等键防止重复提交、按用户限流防止被刷。
- **知识库问答（RAG）**：制度文档按章节切分，用 **bge-m3** 嵌入成向量存入 **pgvector**；
  提问时先检索相关条款再交给模型作答，答案附可点击出处。针对模型"不检索就作答、甚至编造文件名"，
  改为**服务端强制检索**（识别到制度类问题就先检索并注入真实条款）。
- **对话记忆与业务**：会话与消息存 MySQL，每轮把最近的历史拼进上下文以支持追问；
  业务上落地培养计划与毕业学分审核、绩点与专业内排名、排课与冲突检测、选课轮次、考试安排等
  教务规则计算；整套链路在 CI 里用**假模型替代真实模型**自动验证（每次提交都跑）。

> 技术栈：Java 21 / Spring Boot 3.5 / MyBatis / MySQL + Redis / PostgreSQL + pgvector ·
> Spring AI + 本地 Ollama（qwen2.5:7b 对话、bge-m3 嵌入）· Vue 3 + Vite（SSE 流式对话、确认卡片、出处卡片）。

## 这些词各是什么意思（自己先看懂，再写进简历）

| 词 | 一句话解释 | 本项目里在哪 |
|---|---|---|
| **Function Calling（工具调用）** | 模型不会查库，它只能"输出一段结构化数据说我想调用哪个函数、参数是什么"；真正执行的是我们的代码 | `OpenAiClient` 发请求时把工具清单一起带上 |
| **`@Tool` 声明式工具** | 用注解把一个 Java 方法标成"可供模型调用"，并用注解写清"什么时候该用我"；参数说明由框架生成，不用手写 JSON | `ai/tool/declarative/StudentDeclarativeTools` 等三个类 |
| **Agent 循环** | "模型点菜 → 我们端菜（执行工具）→ 把结果告诉它 → 它再说"这个来往过程，循环到它不再请求工具为止 | `ai/runtime/AgentRuntime` |
| **SSE 流式** | 服务器边生成边推给前端（打字机效果），而不是等整段答案算完再返回 | `ai/runtime/SseAgentEventPublisher` + 前端 `useAgentChat.ts` |
| **四道闸门** | 角色白名单（这个角色能不能用这个工具）、参数校验（成绩不能传 200 分）、人工确认（改数据前必须点确认）、审计（每次调用都记录） | `ToolRegistry` / `JsonSchemaToolArgumentValidator` / `ConfirmationGate` / `AiAuditService` |
| **人工确认（HITL）** | 危险操作先挂起、存进 Redis（带有效期），前端弹确认卡片；用户点了才执行 | `ai/confirm/` + 前端确认卡片组件 |
| **RAG** | 让模型"开卷考试"：先从你的文档里查出相关段落，连同问题一起给它，它就不会凭记忆瞎编 | `ai/rag/` 整个包 |
| **嵌入（embedding）** | 把一段文字变成一串数字（向量），语义相近的文字向量也相近，于是可以"按意思"检索而不是按关键词 | 用本地 `bge-m3` 模型生成 |
| **pgvector** | PostgreSQL 的向量扩展，用来存这些向量并做相似度检索 | `RagConfig` + `PgVectorStore` |
| **幂等** | 同一个请求重复提交只生效一次（用户连点两下"确认"不会选两次课） | 审计表上的唯一约束 + 确认令牌 |

## 面试时用三句话讲

1. "大模型不能直接查库改库，所以我把系统能力用 `@Tool` 声明成工具，靠 Function Calling 驱动一个循环：它说要调什么，我这边校验、执行，再把结果喂回去，直到它给出最终答案。"
2. "因为模型不可信，我加了四道闸门：角色白名单、参数校验、危险操作要用户点确认、全量审计；确认之前数据库不会有任何变化。"
3. "知识类问题走 RAG：制度文档切段嵌入到 pgvector，提问先检索出相关条款再让模型作答，答案带出处。"

## 别答错的（三条）

- **退课（`drop_course`）标的是 `WRITE`、不弹确认卡片**——答"退课风险低于选课、不占名额"或"要做成一致也很好改"。
- 11 份制度是**自撰的演示语料**（非某校真实规章），别写成"接入校内真实制度库"。
- RAG 与模型质量指标**没进 CI**（要向量库 + 真实模型，是有意为之）；本地 7B 模型的选路有波动。
