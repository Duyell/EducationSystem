# 简历项目描述（教务系统 · LLM Agent）

> 面向 Agent / 大模型应用方向。与「社区生鲜配送系统」差异化：通用后端条目不写。
> 写法：**每条都点明"用什么做的" + 落到本项目的具体能力**，不堆数字、不写教科书式的通用话。

---

## 可粘贴版本

**项目名称：教务系统（个人项目 · Java 后端 + LLM Agent）**

**项目概述**：为教务系统实现了内嵌 AI 助手——学生可以直接问"我绩点多少""下周有考试吗"，
也能让它选课；回答取自真实数据，涉及改数据的操作必须先经用户确认。

- **实现方式**：用 **Spring AI 的 Function Calling**，把教务接口用 `@Tool` 声明成工具
  （学生、教师、管理员各一套，覆盖绩点、毕业学分审核、课表、考试、选课等；模型只能看到自己角色的那套），
  再用自研的 **Agent 循环**完成"模型请求工具 → 服务端执行 → 结果回填 → 模型继续作答"，
  通过 **SSE** 流式返回。
- **安全闸门**：执行前做角色白名单与参数校验；选课、录改成绩、审批等写操作**不直接执行**，
  而是弹出确认卡片、等用户点确认，**确认前数据库不会有任何变化**；
  每次调用都留审计，重复确认由幂等键挡住。
- **知识问答与记忆**：制度文档按章节切分，用 **bge-m3** 嵌入后存进 **pgvector**，
  提问时先检索相关条款再作答、答案带出处（模型会"不检索就编造文件名"，所以改成**服务端强制检索**）；
  会话历史存 MySQL 并拼进上下文，支持追问。

## 这些词是什么意思（自己看懂再写进简历）

| 词 | 一句话 | 项目里在哪 |
|---|---|---|
| Function Calling | 模型不会查库，它只能"说我要调哪个函数、参数是什么"，真正执行的是我们的代码 | 请求工具清单由 `OpenAiClient` 带上 |
| `@Tool` 声明式工具 | 用注解把 Java 方法标成"可被模型调用"，并写清"什么时候该用"；参数说明由框架生成 | `ai/tool/declarative/` 三个类 |
| Agent 循环 | "模型点菜 → 我们执行 → 结果回填 → 它再说"，循环到它不再请求工具为止 | `ai/runtime/AgentRuntime` |
| SSE | 服务器边生成边推给前端（打字机效果） | `SseAgentEventPublisher` + 前端 `useAgentChat.ts` |
| 四道闸门 | 角色白名单 / 参数校验 / 人工确认 / 审计 | `ToolRegistry`、`JsonSchemaToolArgumentValidator`、`ConfirmationGate`、`AiAuditService` |
| 人工确认 | 危险操作先挂起（存 Redis 带有效期），前端弹卡片，点了才执行 | `ai/confirm/` + 前端确认卡片 |
| RAG | 让模型"开卷考试"：先查出文档里的相关段落，连同问题一起给它 | `ai/rag/` |
| bge-m3 / pgvector | 把文字变成向量（语义相近则向量相近）的本地嵌入模型；PostgreSQL 的向量扩展，负责存和检索 | `RagConfig`、`PgVectorStore` |
| 幂等 | 同一请求重复提交只生效一次（连点两下确认不会选两次课） | 审计表唯一约束 + 确认令牌 |

## 面试三句话

1. "大模型不能直接查库改库，所以我把系统能力用 `@Tool` 声明成工具，靠 Function Calling 驱动一个循环：它说要调什么，我这边校验、执行，再把结果喂回去，直到它给出最终答案。"
2. "因为模型不可信，我加了四道闸门：角色白名单、参数校验、危险操作要用户点确认、全量审计；确认之前数据库不会有任何变化。"
3. "知识类问题走 RAG：制度文档切段嵌入到 pgvector，提问先检索出相关条款再让模型作答，答案带出处。"

## 别答错的（三条）

- **退课（`drop_course`）标的是 `WRITE`、不弹确认卡片**——答"退课风险低于选课、不占名额"或"要做成一致也很好改"。
- 11 份制度是**自撰的演示语料**（非某校真实规章），别写成"接入校内真实制度库"。
- RAG 与模型质量指标**没进 CI**（要向量库 + 真实模型，是有意为之）；本地 7B 模型选路有波动。
