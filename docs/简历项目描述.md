# 简历项目描述（教务系统 · Java 后端 + LLM Agent）

> 更新于 **2026-09-28**（M4 之后）。这一版**针对"Agent / 大模型应用"方向重写**，
> 并刻意与另一段「社区生鲜配送系统」的 Java 项目**做差异化**：
> 凡是那边已经写过的通用后端能力（Spring Security + JWT + RBAC、Redis 缓存、MyBatis/Maven 分层），
> 这里**不再占篇幅**；这里只写那边写不出来的东西。
>
> 数字全部来自仓库内可复现的脚本（`.dsh/` 下 30 个），不是估的。

## 一、与生鲜项目怎么隔离（改写思路）

| 撞车的点 | 生鲜项目已经占了 | 本项目改成怎么写 |
|---|---|---|
| Spring Security + JWT + RBAC + 黑名单登出 | 写得很完整 | **不单独成条**。只在 Agent 的身份模型里带半句："工具以持令牌者的身份执行（身份取自 JWT 校验后的请求属性，不接受参数指定）" |
| Redis 缓存高频查询 / TTL / 主动失效 | 已写 | **删掉**。改写成 Agent 特有的限流（每人每分钟 10 次对话）与 Redis 承载的"确认令牌 TTL 5 分钟" |
| Maven 多模块 + MyBatis + PageHelper + Bean Validation | 通用，另一项目同类 | **压缩成概述里的半句技术栈**，不占 bullet |
| RabbitMQ / Redisson / Lua / 秒杀 | 那是它的高光 | 本项目**不提中间件**，改提 **pgvector 向量检索 + Spring AI + MCP 协议**——这条线只有本项目有 |
| 业务 CRUD | 两边都有 | 本项目把业务写成**"教务规则计算"**（学分审核/绩点排名/冲突检测/六道校验），而不是"增删改查" |

> 一句话原则：**生鲜项目证明"我能写高并发 Java 后端"；教务系统要证明"我能把 LLM 做成可控、可审计、可评测的产品能力"。**
> 两段经历的技术栈重叠度越低，面试官越会当成两种能力看。

## 二、推荐版本（6 条，投 Agent / 大模型应用方向）

**项目名称：教务系统（个人项目 · Java 后端 + LLM Agent）**

**项目概述**：独立开发的教务系统与内嵌智能助手——在真实教务业务（培养计划、绩点、排课、选课、考试）
之上，做出一个**能查真实数据、能办理业务、但改数据前必须由用户确认**的 Agent，
并把同一套能力以 **MCP 协议**开放给外部客户端（Cursor / Claude Desktop）。

- **Agent 运行时与工具面**：自研 Agent 循环（模型↔工具往复编排 + 事件契约，SSE 流式输出），
  把 **33 个业务能力**注册为声明式工具（学生 17 / 教师 7 / 管理员 9，另有 1 个跨角色制度检索工具），
  模型只能看到**自己角色**的工具面；单轮对话限制最多 5 轮工具调用、20 次工具执行，防止失控循环。
  工具的参数 Schema 由框架统一生成、与执行前的校验器**同源**，避免"模型看到的参数"和"实际校验的参数"漂移。
- **四道闸门 + 人工确认（HITL）**：角色白名单 → 参数 Schema 校验 → **危险操作挂起等用户确认** → 全量审计。
  7 个写操作（选课、教学评价、录入成绩、修改成绩、申请开课、申请排课、审批开课）标记为 `DANGEROUS`，
  **用户确认之前数据库不会有任何变化**；确认令牌同时作为**幂等键**（重复提交只执行一次）；
  另有输出护栏（模型把工具调用写进正文时兜住）与频率限制。
- **RAG 制度问答（11 份制度 / 85 个分块）**：按章节切分 + **幂等重建索引**（分块 ID 确定性，
  反复重建不产生重复条款），pgvector + bge-m3 向量检索。实测发现 7B 模型会"**不检索就作答、甚至编造文件名**"，
  于是把检索提到**服务端路由级强制**（识别制度意图 → 自动检索 → 注入真实条款）。
  检索 **Hit@5 12/12（100%）、MRR 0.944**，端到端忠实度严格评测 **9/9**；
  回答附**可点击的出处卡片**，出处随消息落库（刷新不丢）。
- **多轮记忆与对外集成（MCP）**：会话与消息落 MySQL，模型上下文取最近 20 条
  （自研实现而非框架窗口，避免"替换整个会话"导致丢历史）；**MCP server**（官方 Java SDK + SSE）
  把同一工具面开放给外部客户端：默认只放 **14 个只读工具**，`DANGEROUS` **永不外放**
  （它的安全性依赖人工确认，而 MCP 没有这条通道）、`WRITE` 需显式开启；身份取自 token 而非客户端自述，
  外部调用在审计里以 `mcp:<会话号>` 与内部调用区分。已用官方 Inspector 与 **Cursor 实机**验证通过。
- **教务规则计算（业务深度）**：培养计划与毕业学分审核、绩点与**专业内排名**、
  排课与教室推荐（800 间教室 + 上课时间冲突检测）、选课轮次与**六道校验**的选/退课、
  考试安排与冲突检测、开课申请审批流。另有两处"审计友好"设计：
  **成绩变更日志**（谁把谁的成绩从多少改成多少、是界面改的还是 AI 改的）与
  **学业预警**（未通过学分 ≥8 触发，只提示一次、情况变严重才再提示）。
- **质量保障（自动化评测体系）**：**326 项后端测试**（0 失败）+ **11 套链路断言进 CI**
  （工具面 39 / 隐私与审计 41 / 会话 31 / MCP 协议级 / 安全底座 / 业务链路 P1–P4 / 学业预警），
  前端 15 个单测 + 8 套浏览器实机脚本；CI 用**确定性假模型**（OpenAI 兼容 SSE 桩）替代真实模型，
  把"没报错"升级成"**这条链路真的能用**"；真实模型侧另有黄金集评测（75 项断言、工具选路 10/10）。
  这套体系真修出过缺陷，例如：外部协议的工具面在工具注册**之前**被快照，会**静默暴露 0 个工具**；
  以及"客户端用错端点被报成 500"，导致 MCP 客户端放弃协议规定的回退路径。

> 技术栈（概述里一句带过，不占 bullet）：
> Java 21 / Spring Boot 3.5 / MyBatis / MySQL + Redis / PostgreSQL + pgvector ·
> Spring AI 1.0.9 + 本地 Ollama（qwen2.5:7b、bge-m3 嵌入）· MCP Java SDK **0.18.3**（SSE）·
> Vue 3 + Vite + Element Plus（SSE 流式对话、确认卡片、出处卡片，21 个页面）。

## 五、被追问时的答法（已更新到现状）

| 可能被问 | 怎么答 |
|---|---|
| 这个 AI 助手和普通聊天机器人有什么区别？ | 它不只是聊天：**能查系统真实数据、也能改数据**。所以我的重点在两头——按角色划清它"能碰什么"（学生查不到别人的、教师碰不到绩点），以及凡是要改数据就先挂起、等用户点确认，**确认前数据库零变化**。 |
| 为什么要自己写 Agent 循环，不用 LangChain/框架的 tool-calling？ | 我评估过：框架的循环不好插三样东西——危险操作要**挂起等人工确认**（会话线程要能暂停/唤醒并带超时）、输出要**过护栏**、每次调用要**留审计**。自己写循环是为了把这三件事做扎实。代价是多了维护成本，所以我把循环单独抽成 `AgentRuntime`、事件定义成枚举契约，测试可以直接断言事件序列。 |
| 你怎么保证它回答得对？ | 分两层：**能确定的部分**用确定性假模型在 CI 里断言链路（工具面、权限、审计、会话记忆是否真的进了提示词）；**模型质量**用黄金集，跑 10 个典型问题看"有没有选对工具"、再看答案里的数字和数据库是否一致（10/10）。 |
| 遇到过什么真问题？ | 举两个最典型的：① 制度类问题模型**不检索就作答、还编造文件名**——我把它从"提示词里劝它调用工具"改成**服务端路由级强制检索**，模型选不选都会注入真实条款；② 删掉旧的工具实现时发现：**外部协议的工具面是在工具注册之前被快照的**，以前靠"谁先注册"碰巧正确，删掉旧实现后它会**静默暴露 0 个工具**——修法是把顺序变成显式依赖，并补了一条"断言依赖边"的测试（只断言结果抓不住它，实测过）。 |
| 多轮对话怎么做的？ | 会话与消息落 MySQL，模型上下文取最近 20 条。我**没用**框架自带的窗口记忆——它的 `saveAll` 是"替换整个会话"，落库要么丢历史要么消息翻倍。 |
| RAG 效果怎么样？ | 检索层 Hit@5 12/12（100%）、MRR 0.944；端到端忠实度严格评测 9/9。但我会主动说明：**7B 选路本身有波动**（10/10 和 8/10 都出现过），所以质量指标不放 CI，靠本机独占跑。 |
| 为什么把能力开放成 MCP？ | 让别人的模型也能用同一套工具面（Cursor / Claude Desktop），且**不新增第二条执行路径**——外部调用与内置助手最终都走同一个 `ToolRegistry.executeForRole`，所以角色白名单、审计、"界面改的还是 AI 改的"这些语义自动继承。安全上默认只放只读工具，危险工具永不外放。 |

> 更系统的面试准备（八块知识地图、两周按文件读的路径、最值钱的 8 个坑）见
> `docs/Agent学习地图与面试要点.md`。

## 七、诚实边界（别写进简历，但被问到时必须答得上）

- **`drop_course`（退课）标的是 `WRITE`，不弹确认卡片**（选课/评教/录成绩/改成绩/申请开课/申请排课/审批都弹）。
  被问到就答：退课风险低于选课（不占名额、可再选），所以没要求确认；要做成一致也很好改。
- **RAG 的制度文档是自撰的演示文本**（`docs/policies/` 开头写明"演示系统配套制度文本……措辞自拟"），
  不是某所学校的真实规章。别写成"接入校内真实制度库"。
- **RAG 与模型质量评测没进 CI**（要 pgvector + 真实模型），是有意为之；
  能进 CI 的是链路级断言（用确定性假模型）。
- **MCP 未做的**：stdio 传输、按会话动态工具面（现在是一台实例一个角色面）；
  外部客户端的"模型自主调工具"没在付费客户端上跑过（Cursor 免费版能连、其 AI 对话需订阅），
  调用链用官方 Inspector 验证（14 工具、取到真实课程数据、审计留痕）。
- **`docker-compose.yml` 从未实跑**（本机到 Docker Hub 不可达），实际跑法用本机原生三库 + 本地 Ollama。
- **模型评测必须独占运行**：本机 Ollama 串行，两个模型脚本并发会让检索指标假性掉到 25%。
- 单轮上限 5 轮 / 20 次、每人每分钟 10 次这类限制**是保护性设计**，不是缺陷；被问"会不会不够用"时这么答。
