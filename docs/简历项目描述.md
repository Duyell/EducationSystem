# 简历项目描述（教务系统 · 精简版）

> 面向 **Agent / 大模型应用**方向。刻意与「社区生鲜配送系统」差异化：
> 通用后端条目（Spring Security + JWT + RBAC、Redis 缓存、MyBatis 分层）**不写**，
> 只留本项目独有的 Agent 线。数字均来自仓库内可复现脚本。

---

## 可粘贴版本

**项目名称：教务系统（个人项目 · Java 后端 + LLM Agent）**

**项目概述**：独立开发的教务系统与内嵌智能助手——在真实教务业务（培养计划、绩点、排课、选课、考试）之上，
做出一个**能查真实数据、能办理业务、但改数据前必须经用户确认**的 Agent。

- **Agent 能力建设**：自研 Agent 循环（模型↔工具往复编排 + SSE 流式输出），把 **33 个业务能力**
  注册为声明式工具（学生 17 / 教师 7 / 管理员 9），模型只能看到**自己角色**的工具面；
  单轮限制最多 5 轮工具调用、20 次执行，防止失控循环。
- **安全与可控（重点）**：四道闸门——角色白名单 → 参数 Schema 校验 → **危险操作挂起等用户确认**
  → 全量审计。7 个写操作（选课、教学评价、录入/修改成绩、申请开课、申请排课、审批开课）
  **确认前数据库零变化**，确认令牌兼作**幂等键**（重复提交只执行一次）；另有输出护栏与频率限制。
- **RAG 制度问答**：11 份制度 / 85 个分块，pgvector + bge-m3，按章节切分、**幂等重建索引**；
  针对"模型不检索就作答、甚至编造文件名"，改为**服务端路由级强制检索**（识别制度意图 → 自动检索
  → 注入真实条款）。检索 **Hit@5 100%（12/12）、MRR 0.944**，端到端忠实度严格评测 **9/9**；
  回答附可点击出处卡片，出处随消息落库（刷新不丢）。
- **业务规则与质量保障**：培养计划与毕业学分审核、绩点与**专业内排名**、排课与教室推荐
  （800 间教室 + 时间冲突检测）、选课轮次与**六道校验**的选/退课、考试安排；另有
  **成绩变更日志**（谁把谁的成绩从多少改成多少、界面改的还是 AI 改的）与**学业预警**
  （未通过学分 ≥8 触发，只提示一次、变严重才再提示）。**326 项后端测试 + 11 套链路断言进 CI**，
  CI 用**确定性假模型**替代真实模型，把"没报错"升级为"**这条链路真的能用**"；
  真实模型侧另有黄金集评测（75 项断言、工具选路 10/10）。

> 技术栈（一句带过）：Java 21 / Spring Boot 3.5 / MyBatis / MySQL + Redis / PostgreSQL + pgvector ·
> Spring AI 1.0.9 + 本地 Ollama（qwen2.5:7b、bge-m3 嵌入）· Vue 3 + Vite（SSE 流式对话、确认卡片、出处卡片）。

## 被追问时别答错（四条）

- **`drop_course`（退课）标的是 `WRITE`，不弹确认卡片**（选课/评教/录改成绩/申请开课/申请排课/审批才弹）。
  答法：退课风险低于选课（不占名额、可再选），所以没要求确认，要做成一致也很好改。
- **`docs/policies/` 的 11 份制度是自撰的演示语料**（非某校真实规章）——别写成"接入校内真实制度库"。
- **RAG 与模型质量指标没进 CI**（要 pgvector + 真实模型），是有意为之；进 CI 的是链路断言（假模型）。
- **7B 选路本身有波动**（10/10 与 8/10 都出现过）；**`docker-compose.yml` 从未实跑**（本机连不上 Docker Hub）。
