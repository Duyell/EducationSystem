# 简历项目描述（教务系统 · LLM Agent）

> 面向 Agent / 大模型应用方向。与「社区生鲜配送系统」差异化：通用后端条目不写。
> 写法：**客观陈述"做了什么、用什么做的"**；不举例提问、不做宣传式表述、不堆数字。

---

## 可粘贴版本

**项目名称：教务系统（个人项目 · Java 后端 + LLM Agent）**

**项目概述**：教务系统内嵌的 AI 助手模块。基于大模型的工具调用（Function Calling）能力，
将教务业务封装为工具，支持查询教学数据、办理选课与开课审批等业务；
**回答内容基于工具执行返回的数据**，涉及数据变更的操作须经用户确认后执行。

- **技术实现**：工具以 Spring AI 的 `@Tool` 注解声明（参数说明由框架生成），
  按角色注册学生 / 教师 / 管理员三套工具面（含绩点、学分审核、课表、考试、选课等）；
  自研编排循环负责处理模型返回的工具调用请求、执行工具、回填执行结果并请求模型继续生成，
  直到模型不再请求工具；结果通过 SSE 流式返回；多轮对话携带 MySQL 中保存的历史消息。
- **安全控制**：工具执行前校验角色白名单与参数合法性；选课、成绩录入与修改、开课与审批等写操作
  挂起为待确认，用户确认后才执行，**确认前不产生任何数据变更**；
  每次调用写入审计记录，确认令牌同时作为幂等键。
- **知识问答**：制度文档按章节切分，用 bge-m3 生成向量存入 pgvector；提问时先检索相关条款，
  将条款作为工具结果交给模型，回答附出处引用。
  针对模型存在"未检索即作答"的情况，增加服务端强制检索。

## 这些词是什么意思（自己看懂再写进简历）

| 词 | 一句话 | 项目里在哪 |
|---|---|---|
| Function Calling | 模型不能直接查库，它只能"说我要调哪个函数、参数是什么"，真正执行的是我们的代码 | 请求工具清单由 `OpenAiClient` 带上 |
| `@Tool` 声明式工具 | 用注解把 Java 方法标成"可被模型调用"，并写清"什么时候该用"；参数说明由框架生成 | `ai/tool/declarative/` 三个类 |
| 编排循环 | "模型要求调用工具 → 执行 → 结果回填 → 再请求模型"，直到模型不再请求工具 | `ai/runtime/AgentRuntime` |
| SSE | 服务器边生成边推给前端（打字机效果） | `SseAgentEventPublisher` + 前端 `useAgentChat.ts` |
| 四道闸门 | 角色白名单 / 参数校验 / 人工确认 / 审计 | `ToolRegistry`、`JsonSchemaToolArgumentValidator`、`ConfirmationGate`、`AiAuditService` |
| 待确认（HITL） | 危险操作先挂起（存 Redis 带有效期），前端弹确认卡片，用户点了才执行 | `ai/confirm/` + 前端确认卡片 |
| RAG | 先从文档里查出相关段落，连同问题一起交给模型 | `ai/rag/` |
| bge-m3 / pgvector | 把文字转成向量的本地嵌入模型；PostgreSQL 的向量扩展，负责存储与相似度检索 | `RagConfig`、`PgVectorStore` |
| 幂等键 | 同一请求重复提交只生效一次（连点两下确认不会选两次课） | 审计表唯一约束 + 确认令牌 |

## 面试三句话

1. "大模型不能直接查库改库，所以我把系统能力用 `@Tool` 声明成工具，靠 Function Calling 驱动一个循环：它说要调什么，我这边校验、执行，再把结果喂回去，直到它给出最终答案。"
2. "因为模型不可信，我加了四道闸门：角色白名单、参数校验、危险操作要用户点确认、全量审计；确认之前数据库不会有任何变化。"
3. "知识类问题走 RAG：制度文档切段嵌入到 pgvector，提问先检索出相关条款再让模型作答，答案带出处。"

## 别答错的（三条）

- **退课（`drop_course`）标的是 `WRITE`、不弹确认卡片**——答"退课风险低于选课、不占名额"或"要做成一致也很好改"。
- 11 份制度是**自撰的演示语料**（非某校真实规章），别写成"接入校内真实制度库"。
- RAG 与模型质量指标**没进 CI**（要向量库 + 真实模型，是有意为之）；本地 7B 模型选路有波动。
