# 简历项目描述（教务系统 · LLM Agent）

> 面向 Agent / 大模型应用方向。与「社区生鲜配送系统」差异化：通用后端条目不写。
> 写法：**概述写教务与助手功能；技术实现写清整个 Agent 循环；用专业术语但说人话。**

---

## 可粘贴版本

**项目名称：教务系统（个人项目 · Java 后端 + LLM Agent）**

**项目概述**：教务系统（覆盖培养计划与毕业学分审核、绩点与专业内排名、排课与教室推荐、
选课轮次与选/退课、考试安排等教学管理业务）内嵌的 AI 助手：支持用自然语言查询教务数据
（学分、绩点、课表、考试）、以对话方式办理选课与开课审批、制度问答与多轮追问；
回答内容基于工具执行返回的数据，涉及数据变更的操作须经用户确认后执行。

- **技术实现（Agent 循环）**：基于 **Spring AI 的 Function Calling**。每轮请求模型前组装
  **System Prompt**（角色、当日日期、可用工具摘要与行为规则）、该角色的**工具清单**
  （用 `@Tool` 声明，参数 **Schema** 由框架生成）与会话记忆中的历史消息；模型返回
  **工具调用请求**后，服务端做参数校验并执行工具，把执行结果作为 **tool 消息回填上下文**，
  再次请求模型——**循环直到模型不再请求工具**；最终回答经 **SSE** 流式推送，
  并对单轮的工具调用轮次与总次数设上限，防止失控循环。
- **安全控制（四道闸门）**：**角色白名单 → 参数 Schema 校验 → 危险操作人工确认（HITL）→ 审计留痕**。
  选课、成绩录入与修改、开课与审批等写操作会挂起为待确认（**Pending Action** 存 Redis、带有效期），
  用户确认后才执行，**确认前不产生任何数据变更**；确认令牌兼作**幂等键**，
  另有**输出护栏**与**按用户限流**。
- **知识问答（RAG）**：制度文档按章节**切分（Chunking）**，用 **bge-m3** 生成**嵌入（Embedding）**
  写入 **pgvector**，检索按**余弦相似度**取 **Top-K**；命中的条款作为工具结果**注入上下文**，
  回答附带**出处引用**。针对模型"未检索即作答"的情况，增加服务端**意图识别与强制检索**。

## 这些词是什么意思（自己看懂再写进简历）

| 词 | 一句话 | 项目里在哪 |
|---|---|---|
| Function Calling | 模型不能直接查库，它只能"说我要调哪个函数、参数是什么"，真正执行的是我们的代码 | 请求工具清单由 `OpenAiClient` 带上 |
| System Prompt | 每轮都发给模型的"角色说明书"：你是谁、今天几号、有哪些工具、要守什么规矩 | `resources/prompts/*.st` |
| `@Tool` 声明式工具 | 用注解把 Java 方法标成"可被模型调用"，并写清"什么时候该用"；参数说明由框架生成 | `ai/tool/declarative/` 三个类 |
| 工具清单（tools） | 随请求一起发给模型的"可用工具目录"，模型只能从里面挑 | `ToolRegistry.toToolsPayload` |
| 参数 Schema 校验 | 执行前用同一份参数定义再校验一次（成绩不能传 200 分） | `JsonSchemaToolArgumentValidator` |
| tool 消息回填 | 工具执行完，把结果按 `role=tool` 的格式追加进对话，模型才"看得到"结果 | `ai/runtime/AgentRuntime` |
| 编排循环 | "模型要求调用工具 → 执行 → 回填 → 再请求模型"，退出条件是模型不再请求工具 | 同上 |
| SSE | 服务器边生成边推给前端（打字机效果） | `SseAgentEventPublisher` + 前端 `useAgentChat.ts` |
| 四道闸门 | 角色白名单 / 参数校验 / 人工确认 / 审计 | `ToolRegistry`、`JsonSchemaToolArgumentValidator`、`ConfirmationGate`、`AiAuditService` |
| HITL / Pending Action | 危险操作先挂起（存 Redis 带有效期），前端弹确认卡片，用户点了才执行 | `ai/confirm/` + 前端确认卡片 |
| 输出护栏 | 模型把"工具调用"写成正文时，服务端接住并纠正 | `ai/guard/ToolCallTextGuard` |
| 幂等键 | 同一请求重复提交只生效一次（连点两下确认不会选两次课） | 审计表唯一约束 + 确认令牌 |
| Chunking / Embedding | 把制度文档切成小段；把一段文字转成向量（语义相近则向量相近） | `PolicyChunker`、本地 `bge-m3` |
| pgvector / 余弦相似度 / Top-K | PostgreSQL 的向量扩展，按向量夹角算相似度，取最相关的前 K 段 | `RagConfig`、`PolicySearchService` |

## 面试三句话

1. "大模型不能直接查库改库，所以我把系统能力用 `@Tool` 声明成工具，靠 Function Calling 驱动一个循环：它说要调什么，我这边校验、执行，再把结果按 tool 消息回填，直到它不再请求工具、给出最终答案。"
2. "因为模型不可信，我加了四道闸门：角色白名单、参数校验、危险操作要用户点确认、全量审计；确认之前数据库不会有任何变化。"
3. "知识类问题走 RAG：制度文档切段嵌入到 pgvector，提问先检索出相关条款再让模型作答，答案带出处。"

## 别答错的（三条）

- **退课（`drop_course`）标的是 `WRITE`、不弹确认卡片**——答"退课风险低于选课、不占名额"或"要做成一致也很好改"。
- 11 份制度是**自撰的演示语料**（非某校真实规章），别写成"接入校内真实制度库"。
- RAG 与模型质量指标**没进 CI**（要向量库 + 真实模型，是有意为之）；本地 7B 模型选路有波动。
