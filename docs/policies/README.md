# 教务制度文件（JW 系列）— 索引与审计口径

> 本目录是**演示系统配套的制度文本**，用途有两个：
> 1. **作为 RAG 知识库的语料**（M3 阶段）：让智能助手回答政策类问题时**依据条款作答并给出出处**，
>    而不是靠大模型的常识编造；
> 2. **作为规则的可读来源**：系统里那些"为什么这么算"的判断，除了代码，还能看到一份人能读的规定。
>
> 生成于 2026-09-20。**规则数值全部取自系统实现**；系统未实现的部分参考国内高校通行做法撰写，措辞自拟，
> **不逐字照搬任何学校的文件**。

## 四、关键常量对照表（审计时逐条核这几行就够）

| 规则 | 文档写的值 | 代码位置（可核对） |
|---|---|---|
| 及格线 | **60 分**（可配置，默认 60） | `gpa_rule.pass_score`；`GpaServiceImpl.currentPassScore()` |
| 总成绩 | **平时 0.4 + 考试 0.6**，3 位小数四舍五入 | `ScoreServiceImpl.USUAL_WEIGHT/EXAM_WEIGHT/SCORE_SCALE` |
| 单科绩点 | 成绩 < 60 → 0；否则 **成绩 ÷ 10 − 5** | `GpaServiceImpl.gradePoint()` |
| 绩点示例 | 60→1.0、75.76→2.576、87.365→3.7365、100→5.0、59.9→0 | `GpaServiceTest`（13 条逐条断言） |
| 补考通过 | 一律按 **60 分**记载（绩点 1.0） | `GpaServiceImpl.effectiveScore()` |
| GPA | Σ(绩点×学分)/Σ学分，**仅通过课程**，4 位小数 | `GpaServiceImpl.calcGpa()`（`GPA_SCALE = 4`） |
| 专业内排名 | 同专业同年级、GPA 降序、**同分同名次**（严格高者数 + 1） | `GpaServiceImpl.rankInMajor()` |
| 通过判定 | 总成绩 ≥ 60 **或** 补考 ≥ 60（**唯一实现**） | `GpaServiceImpl.isPassed()` |
| 毕业条件 | 必修**全部通过** + 选修**学分达标** + 总学分达标 | `CreditServiceImpl.auditGraduation()` |
| 学分取值 | 取**实际修读课程**的学分（`course.credit`），不是培养计划里的 | `CreditServiceImpl.creditOf()` |
| 选课六道校验 | ①轮次开启（含时间窗）②适用范围 ③学分上限 ④是否已修过（同代码已通过）⑤时间冲突 ⑥容量；代码执行顺序＝状态判定（开关→范围→时间窗）→ ③→④→⑤→⑥ | `CourseSelectionServiceImpl.selectionBlocker()`（**全项目唯一实现**，与设计文档 §4.3(6) 一致） |
| 轮次学分上限 | 每轮可配置（示例 **30**） | `selection_round.max_credits` |
| 上课时间冲突 | 同 term + 同星期 + 节次重叠 + 周次重叠；**闭区间**（3-4 与 4-5 算冲突） | `ScheduleServiceImpl.checkConflict()` / `ClassTimeMapper` |
| 考试冲突 | 连续时钟区间；**半开区间**（11:00 结束 vs 11:00 开始**不算**冲突） | `ExamServiceImpl.checkConflict()` |
| 一天节次 | **1~10 节**；星期 1~7 | `ClassTime.MIN_PERIOD/MAX_PERIOD/MIN_WEEKDAY/MAX_WEEKDAY` |
| 周次 | 任意区间（支持 9-16 周等非整学期）；不做单双周 | `ScheduleServiceImpl.validateSlot()` |
| 教室 | **800 间**：教1~教8 × 10 层 × 10 间；NORMAL 648 / LAB 80 / MULTIMEDIA 72；容量 60~240 | `room` 表（程序化生成） |
| 教室推荐顺序 | 容量 → 楼栋 → 楼层 → 房间号（**刻意不用自增 id**） | `RoomMapper.pickFreeRooms()` |
| 评教 | **5 星制 1~5**、每生每课一次、提交后不可改 | `evaluate_teacher` 工具 Schema；`uk_eval_course_student` |
| 成绩录入权限 | 仅**本人所授课程**（服务端强制校验） | `CourseService.isCourseOfTeacher()` |
| 危险操作 | 确认卡片后方可执行（选课/录成绩/开课申请/排课申请/审批） | 工具 `RiskLevel.DANGEROUS` + `ConfirmationGate` |

## 五、怎么审（建议顺序）

1. **先审第三节那 5 处**——只有这几处需要你做决定，其余是"文档照代码写"。
2. **再抽查第四节的常量表**：随便挑 3~5 行，让智能助手（或直接查库）核对一遍数值。
   例如问助手"补考通过算几分"，它应回答 60 分并引用 JW-03。
3. **最后读 JW-01 / JW-06 / JW-08 的【制度】条文**（学业预警标准、教室调配、评教使用），
   这些数值是我参考通行做法填的**示例值**，需要你确认或替换。

**发现冲突时的处理原则**（写在各文件末尾，也说一遍）：
> **以系统实际行为为准**，然后**改文档**；如果认为文档才对，那就是**代码缺陷**，要修代码并加回归测试。

## 六、与后续开发的关系

- **M3（RAG 阶段）**：ETL 直接读取本目录的 Markdown → 按标题切块 → 用本地 `bge-m3` 嵌入 → 检索后把
  「文档名 + 章节」作为引用来源回给前端。因此本目录**每个文件都按条款分节**，就是为了切块与引用。
- **M5（评测阶段）**：可用本目录出题（例如"补考算几分""考试接着考算不算冲突"），
  断言"引用正确条款 + 答案与系统行为一致 + 文档里没有的规则要如实说不知道"。
- **新增制度时**：编号顺延（JW-11…），在本文件第二节登记，并在该文件末尾补"与系统实现的关系"表。

## 七、维护纪律

1. **任何代码规则变更，必须同步检查本目录**（数值型规则尤其）：文档与代码不一致 = 缺陷。
2. 本目录文件**不要写死运行期数据**（如具体选课日期、某学生的成绩），只写规则与示例结构。
3. 中文标点与术语保持一致：如统一用"及格线 60 分""平均学分绩点（GPA）""课程代码"。
