# 教师成绩录入与修改规范

> 文档编号：**JW-09**　｜　适用范围：任课教师、教学管理人员　｜　版本：v1.0（2026-09-20）
> 图例：**⚙** = 系统已自动校验，数值与代码一致；**【制度】** = 管理制度条文，系统当前不自动校验。

---

## 1. 总则

1.1 任课教师负责所授课程的成绩录入与复核。成绩一经录入即进入学业记录，影响学生学分、绩点与毕业审核。**⚙**

1.2 **教师只能录入、修改本人所授课程的成绩**，无权操作其他教师的课程。**⚙**

1.3 成绩的计算规则（权重、精度、及格判定、绩点换算）见 JW-05，本文档只规定**录入与修改的操作规范**。

## 2. 可录入的范围

2.1 教师可录入**本人所授课程**的**已选课学生**成绩。**⚙**
> 系统在服务端校验课程归属（不是靠提示词约束）：非本人课程直接返回"无权限为该课程录入成绩/修改该成绩"。

2.2 学生须**已选该课程**才能录入成绩（成绩记录以"课程 + 学生"为唯一键）。**⚙**

2.3 **【制度】** 未选课学生（如旁听、跨专业选修未办理手续者）不得录入成绩；确需录入的，应先完成选课手续。

## 3. 录入内容与计算

3.1 录入项为**平时成绩**与**考试成绩**两项。**⚙**

3.2 **总成绩由系统计算**：总成绩 = 平时成绩 × 0.4 + 考试成绩 × 0.6，保留 3 位小数。**⚙**
教师**不能直接填写总成绩**；系统不信任外部传入的总成绩。

3.3 未填写的分项按 **0 分**参与计算（例如只录平时成绩时，总成绩 = 平时成绩 × 0.4）。**⚙**

3.4 系统在录入时**自动判定是否通过**（≥ 60 分为通过，含补考判定），并写入记录。**⚙**

3.5 成绩为百分制，精度 3 位小数；系统**未强制**限制取值范围，教师应按规范录入 0~100 的分数。**⚙**（现状说明）

3.6 **同一名学生在同一门课上只有一条成绩记录**。重复录入时系统提示"该学生此课程已有成绩记录，请使用修改功能"。**⚙**

## 4. 修改成绩

4.1 成绩需要更正时，通过**修改**功能进行，**不得删除后重新录入**。**⚙**

4.2 修改时可**只提交需要变更的分项**，未提交的分项**保留原值，不会被清零**。**⚙**

4.3 修改后系统**自动重新计算总成绩与通过状态**。**⚙**

4.4 成绩的录入与修改属于**重要变更**：系统在执行前要求人工确认，确认后才真正写入。**⚙**

4.5 **所有成绩变更一律留痕**（2026-09-22 实现，作者拍板）：无论**界面直接操作**还是**经智能助手**，
新增/修改/删除成绩都会写入**成绩变更日志**（`score_change_log`），记录：

| 记什么 | 说明 |
|---|---|
| 操作人 | 学号/工号/用户名 + 角色 |
| 时间 | 记录时间 |
| 对象 | 课程、学生、成绩记录 id（删除后仍保留） |
| 操作 | `INSERT` / `UPDATE` / `DELETE` |
| **改前 → 改后** | 平时/考试/补考/总分/是否通过的**完整快照** |
| 来源 | `UI`（界面或接口）或 `AI`（智能助手） |

4.6 成绩变更日志**只增不删**，且**仅管理员可查**（`GET /score/change-log`，可按学号/课程/操作人筛选）。
教师与学生无权查询该日志。**⚙**

4.7 **记录失败不影响成绩本身**：日志写入异常会被记录到服务端错误日志，但**不会**让一次正常的成绩录入失败。**⚙**

> **设计说明**：留痕的挂钩点只有一处（`ScoreServiceImpl` 的 add/update/delete）——
> 它是全部成绩写入的必经之路，所以界面与 AI 两条路径都不可能绕过。
> "谁在操作、来源是界面还是 AI"由 `ChangeContext` 在两个边界设置（`ScoreController` 与 `ToolRegistry`），
> 而不是要求每个调用点自己传参（那样漏一处就丢一条留痕）。

## 5. 复核与责任

5.1 **【制度】** 教师应在提交前核对成绩与平时记录，确保成绩真实、准确、完整。

5.2 **【制度】** 成绩录入完成后进入**复核期**（一般 3 个工作日），复核期内如发现错误应及时更正。

5.3 **【制度】** 复核期结束后，成绩原则上不再变更。确有错误的，须填写成绩更正申请，经教研室主任与教务处审批后方可更正。

5.4 **【制度】** 因教师未按时录入、录入错误而影响学生评奖评优、毕业等的，按学校教学事故认定办法处理。

## 6. 时限要求

6.1 **【制度】** 成绩应在课程考核结束后 **两周内**全部录入完毕。

6.2 **【制度】** 期末考试期间，原则上应在该课程考试结束后 **5 个工作日内**完成录入与复核。

6.3 **系统现状**：系统**未实现成绩录入时限的强制约束**（无截止时间字段与到期提醒）。**⚙**（现状说明）

## 7. 附则

7.1 本规范由教务处负责解释。

7.2 与系统行为不一致时，以系统实际行为为准，并及时修订本文件。

### 与系统实现的关系（供审计）

| 条款 | 系统是否自动校验 | 依据 |
|---|---|---|
| 1.2 / 2.1 只能操作本人课程 | ⚙ 是 | `CourseService.isCourseOfTeacher` 在 `enter_score`/`update_score` 中强制校验（服务端，非提示词） |
| 2.2 以"课程+学生"为唯一键 | ⚙ 是 | 唯一约束 `uk_score_course_student` |
| 3.2 总分由系统计算（40:60、3 位小数） | ⚙ 是 | `ScoreServiceImpl.calcTotal`（AI 助手侧亦调用它，见 `AgentScoreEntryTest`） |
| 3.4 自动判定通过 | ⚙ 是 | `ScoreServiceImpl.calcPassed` → `GpaServiceImpl.isPassed` |
| 3.6 重复录入被拦 | ⚙ 是 | `enter_score` 先查 `scoreMapper.select(courseId, studentId)` 并提示改用修改 |
| 4.1–4.3 合并修改、自动重算 | ⚙ 是 | `ScoreServiceImpl.update`（未传分项从库中取值）+ `ScoreMapper.xml` 动态列 |
| 4.4 修改需人工确认 | ⚙ 是 | 工具风险等级 `DANGEROUS` → 确认卡片（HITL） |
| 4.5 AI 调用留痕 | ⚙ 是 | `ai_tool_audit`（参数、结果、状态、耗时、确认令牌） |
| 4.5–4.7 **界面变更也留痕** | ⚙ **是（2026-09-22 已实现）** | 表 `score_change_log`；挂钩点 `ScoreServiceImpl.add/update/delete`（全部写路径的必经之路）；来源与操作人由 `ChangeContext` 在 `ScoreController`（UI）与 `ToolRegistry.executeForRole`（AI）设置 |
| 4.6 日志仅管理员可查 | ⚙ 是 | `LoginInterceptor` 规则 `/score/change-log` → ADMIN（**排在 `/score/**` 之前**），教师/学生 403、匿名 401 |
| 3.5 成绩范围 0~100 | ⚙ **是（2026-09-22 已实现）** | `ScoreServiceImpl.validateRange`（add 与 update 都过） |
| 6.3 录入时限 | ❌ 未实现 | 无截止时间字段与到期提醒 |
