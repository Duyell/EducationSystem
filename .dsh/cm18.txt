接入
- 父 pom 引入 spring-ai-bom:1.0.9（与 Spring Boot 3.5 兼容，本机 m2 已有）
- edu-api 引入 spring-ai-starter-model-ollama + spring-ai-client-chat + chat-memory 自动配置
- application.yml 增加 spring.ai.ollama.*（与既有 ai.* 并存：前者驱动框架，后者驱动手写 OpenAiClient）

  SpringAiWiringTest 2 项（默认只验 Bean；真实调用用 -Dai.live=true 显式打开，已手工跑通"收到"）

两个环境坑（已解决，写入接续指南）
1) 离线构建认领不了本地 Spring AI 制品：本机 m2 中这批制品来源 id 是 aliyun-maven（镜像），
   Maven -o 模式要求来源 id 在当前仓库列表里，否则报 "spring-ai-bom:pom:1.0.9 (present, but unavailable)"。
   修法：父 pom 显式声明同 id 仓库（未改 Maven 全局配置、未改本地仓库文件）。
2) Spring AI 的传递依赖本地不全（spring-retry/spring-webflux/micrometer-core…），需联网拉一次；
   沙箱不许写 ~/.m2（FileNotFoundException 拒绝访问）→ 一次性提权跑同一构建命令，之后 mvn -o 正常。

护栏补漏（由基线评测当场发现）
- 模型这次没吐完整块，而是吐了**没有配对的 </tool_call>** 加字符残渣（"imonial"），
  原护栏只处理完整块与裸 JSON，落单标签漏给了用户 → 评测断言变红
- 修法：stripStrayTags 清掉落单的 <tool_call> / </tool_call>（收尾段同样处理）；补 2 条单测
